# Requirement trace

Maps every requirement identifier to the tests that cover it and the commits that delivered it. A requirement with no test is a gap and is listed as one.

- **Identifiers.** `AT-n` is acceptance test n in SPEC 11. `D-n` is the n-th decision in SPEC 2's table. Other rules are cited as a SPEC section plus rule name. Spike decisions are cited as `spikeN` (SPIKE-WINDOWS.md, decisions 1 to 6).
- **Test names.** Every test name starts with its identifier: `atN_`, `dN_`, `sN_` or `spikeN_` (DECISIONS B-40). This file is checked against the test names with `rg -o "fn ((at|d|s|spike)[0-9]+_[a-z0-9_]+)" -r '$1' crates`.
- **States.** *Covered*: the requirement's own test exists and passes. *Partial*: tests cover the shared types or formulas it rests on; the end-to-end test is still owed by the named stream. *Gap*: no test yet.
- **Last updated.** 17 November 2026, after the replay command of step 21 (B-172). Tests are in `crates/sm-core`, `crates/sm-spatial`, `crates/sm-embed`, `crates/sm-capture`, `crates/sm-store`, `crates/sm-cli`, `crates/sm-share` and `crates/sm-daemon`. Windows: 751 tests: sm-core 102 (one test is Unix-only), sm-embed 56 with the real-model binary, sm-spatial 47, sm-capture 46, sm-store 89, sm-cli 149, sm-share 95 and sm-daemon 167. The RC4, RC6 and RC7 reproductions pass with the judge. In the full run one judge test failed, `s16_a_rate_limit_waits_until_its_reset_time`: it set the reset time before the daemon started, so a late first call shortened the wait it measured. The test now sets the reset at the first call (B-168); its binary then passed four runs in a row. The platform-only tests are in H's report, h-report.md, and K's, k-report.md. Linux (Docker, `rust:1.95-trixie`), last run after package K and to be run again in section F: 658 pass: sm-core 98, sm-embed 55 unit tests and the real-model binary, sm-spatial 47, sm-capture 35, sm-store 67, sm-cli 132, sm-share 93 and sm-daemon 130. Format and clippy are clean on both. The real-model binary skips in Docker unless the model folder is mounted (stream B mounted it for its Linux readings, B-58). `claude plugin validate` runs only where `claude` is on `PATH`, so it is skipped in Docker.
