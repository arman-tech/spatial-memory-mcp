# Stream F: `sm-share`

## Goal

Build `crates/sm-share`, the library behind team sharing and moving stores: the shared-file format (a strict front-matter writer and parser, path naming, the `.gitattributes` rule), `share`, `sync` through git, `migrate` from a version 1 or 2 JSON export, and whole-store `export` and `import` as JSON Lines. Each is a plain function over `sm-store` and the `sm-core` traits (`Chunker`, `SecretScanner`). Stream E builds the daemon at the same time and reaches these functions through its `SharingOps` trait; the lead writes that adapter in phase 3 (B-79).

**SPEC 14 done when:** "Sharing and migration tests pass, using the secret scanner delivered by stream G".

## You own

- `crates/sm-share/` (new library crate; depends on `sm-core` and `sm-store`; on Windows, `windows-sys` for `CREATE_NO_WINDOW`, whose `Win32_System_Threading` feature the root already enables). `[dev-dependencies]`: `sm-core` with `test-support`, `sm-capture` for the real `RegexSecretScanner` (B-8), and `tempfile`.
- Nothing else. The daemon wiring, `MIGRATION.md` and the CLI subcommands are the lead's in phase 3.

## Build

1. **The shared-file format** (SPEC 9, "Shared file format").
   - **Writer.** Front matter keys in SPEC 9's order: `schema: 1`, `id`, `type`, `status`, `date`, `supersedes`, `anchors`, `tags`, `commit`. Decide how an absent optional key is written (SPEC 9's example writes `supersedes:` with no value), and write it the same way every time. `date` is the creation date in UTC. Anchors are `kind:name`; tags and anchors are one-line lists. Then `# <title>`, a blank line and the body. LF line endings only, one newline at the end. The same memory always gives the same bytes.
   - **Parser.** Strict and small, not a YAML library: single-line scalars and one-line lists only, the keys above only, `schema: 1` only. Every failure names the line and the reason. The title is the first level-1 heading of the body; headings after it stay in the body. Validate what it reads with the store's rules (B-19 for tags and anchors, `MemoryId` for `id` and `supersedes`, the type and status names).
   - **Round trip.** `parse(render(m))` gives back the type, status, date, supersedes, anchors, tags, commit, title and body; `render(parse(file))` gives back the same bytes. Say how the body is normalised (line endings, trailing newlines) and test it.
   - **Text hash** (B-78): the SHA-256 of the Markdown part exactly as `render` writes it. Expose one function that computes it for a memory and for a parsed file, so `share` and `sync` cannot disagree. A memory with no title is rendered, and hashed, with `derive_title` (B-18).
   - **Path.** `.spatial-memory/shared/<type>/<slug>--<last 8 characters of the id>.md` (SPEC 9; its rule 1 shorthand `<id>.md` is superseded by the format section). Decide the slug rule (characters, length cap, the fallback for an empty slug) and record it; keep paths short enough for Windows.
   - **`.gitattributes`** in `.spatial-memory/shared/` so a Windows checkout keeps LF. Decide the rule, write it when it is missing, and leave an existing file alone.
2. **`share`** (SPEC 9 rules 1 and 2, "Security"; AT-9).
   - Write each listed memory of the project into the working tree at `repo_root`. Nothing is committed or pushed.
   - Refuse each problem memory in `ShareReply.refused` and write the rest: an id that is not in the project (`not_found`), a memory that is already shared (`shared_read_only`, naming its file: the fix goes through the repository), and a file that still matches the scanner (`secret_detected`).
   - Redact the title and body with the scanner and list the kinds in `SharedFile.redactions`. Then scan the whole rendered file, front matter included: tags and anchors are not redacted, so a match there refuses the memory, and no file is written for it.
   - `commit` is the memory's `provenance.commit_sha` when it has one.
   - A merged memory is written as `status: superseded` with its own `supersedes`, if any (B-73).
   - Sharing a memory again replaces its earlier file, found by the `--<last 8>.md` suffix, even when the type or slug changed. A path that holds a file for a different id is refused (`invalid_input`).
   - `share` does not change the memory. `sync` adopts it after the pull request merges (B-78). If redaction changed the text, the hashes differ and `sync` reports it; say so in the reply's documentation.
   - `repo_root` without a `.git` entry (a folder, or a file in a worktree) fails with `not_git_repository`, even though the daemon checks first (B-79).
3. **`sync`** (SPEC 9 rules 3 to 5, "Change detection before reading"; B-78 in full).
   - **Git.** Run git directly, never through a shell, at the repository root, with arguments as a list, `GIT_TERMINAL_PROMPT=0`, and `CREATE_NO_WINDOW` on Windows (`std::os::windows::process::CommandExt::creation_flags`). Use `rev-parse` for `HEAD` (a repository with no commits has nothing to sync, and is not an error), `ls-tree -r -z --full-tree HEAD -- .spatial-memory/shared/` for paths, modes and blob ids, and one `cat-file --batch` process for the blobs you read. Only regular blobs ending in `.md` count; anything else under the folder (symbolic links, submodules, other files) is skipped and reported. Choose the error code and next action for git missing from `PATH` or failing (for example a repository git refuses as "dubious ownership"), carrying git's message, and record the choice.
   - **What to read.** A listed file whose path and blob id both equal a stored `SyncMark` of this project is unchanged and not read. Read every other file. Decide a size limit for one file and record it.
   - **Applying a file**, per B-78: a new id is inserted with origin `shared`, provenance source `sync`, `Access::Sync`, chunks from the `Chunker` with `ChunkParams.index_cap` `None`, all pending, then marked with `record_sync`. A known shared id is revised: with a `ContentChange` and new pending chunks when the text hash changed, otherwise the type, status, tags and anchors only. A local memory of this project with the same id is adopted only when the text hashes are equal. An id in another project, or in two files, is a `FileIssue` and neither file is applied. A file that does not parse is a `FileIssue` and never stops the sync.
   - **`supersedes`.** Insert in an order that puts targets before the memories that supersede them. A target missing from the store and from the files: decide (for example insert without it and keep the id in `provenance.extra`, with a `FileIssue`), and record it. A later change to `supersedes` on a known memory is not applied: the store writes `supersedes_id` only at insert (B-73, B-78); apply the rest and report it.
   - **Gone files.** A shared memory of this project whose file is not at `HEAD` is retracted (status `retracted` under `Access::Sync`, never deleted) and listed in `removed`. When the file comes back, even with the same blob id as before, the next `sync` applies it again: make sure the unchanged-file shortcut cannot skip it.
   - **`dry_run`** computes the same reply and writes nothing.
   - The reply counts `added`, `updated`, `removed`, `unchanged` and `errors` exactly; every listed file is in exactly one of them.
4. **`migrate`** (SPEC 10; AT-8; B-12, B-14, B-18, B-35, B-79).
   - **Read** the version 1 or 2 export as a JSON array, record by record, without keeping vectors in memory (a 10,000-record export with vectors is about 80 MB). Two passes are fine: the first validates every record and resolves every project, the second writes.
   - **Before writing anything:** two projects with the same name fail with `invalid_input`; records without `project` go to `default_project`, else `cwd_project`, else fail with `project_unresolved` (B-35). Nothing is written, and no project is created, when either fails.
   - **Projects** by B-79's three steps, with `ensure_project`. `projects_created` lists the new names.
   - **Fields** (SPEC 10's table): `id` via `MemoryId::from_v1` (B-12); `content`; `created_at` and `updated_at`, naive values read as UTC (B-18); `content_hash` kept when it equals B-14's hash of the content as stored, otherwise the stored content's hash with the version 1 value kept in `imported`; `namespace` becomes a tag unless it equals the project name or is empty; `tags` become tags; `source` and `metadata` go into `provenance.extra`; `importance`, `access_count`, `last_accessed` and `expires_at` go into `imported`; `vector` is dropped; `type = note`, `status = active`, origin `local`, provenance source `import`, the default importance.
   - **Never drop a record** (SPEC 12). Redact the content with the scanner and count `redacted`; do not apply the capture skip rule. A tag that breaks B-19 is cleaned or left out, with the original kept in `imported`; the record is still stored. A record that cannot be stored at all (for example empty content) is an `ImportIssue`. A record whose content hash the project already holds under another id is not stored by the store (B-76): report it as an `ImportIssue` that names the memory holding that content, so the report shows it.
   - **Resumable.** Insert in transactions of a bounded size, so an interrupted run loses at most one batch and keyword search works on what is stored. A second run counts every stored id in `skipped_existing` and inserts nothing new. Chunks are stored pending; `pending_embeddings` is the number of chunks queued.
   - **The report** keeps `read = inserted + skipped_existing + issues.len()` (CONTRACTS 5).
5. **`export` and `import`** (B-77 in full).
   - **Export.** Header, then projects, memories (with `iter_memories`) and links, one JSON object per line, LF. Refuse an existing file; write a temporary file in the same folder and rename it. `project` selects one project by name (`not_found`, or `invalid_input` for two). Define your own line structures, so a change to an `sm-core` type cannot change the file format silently. The same store gives the same bytes apart from the header.
   - **Import.** Refuse an unknown `format` or a newer `version` before writing. Projects by identity key with `ensure_project`. Memories keep their ids, origin, status, provenance, anchors, `supersedes_id` and `imported`, inserted with targets before the memories that supersede them; an id already present counts in `skipped_existing`. Choose the `Access` import writes with (it restores shared memories and their supersessions as they were) and record it. Scan and redact content as `migrate` does. A link whose ends are missing is an `ImportIssue`. Keep the `ImportReport` invariant, and decide how links and projects are counted so it holds.
   - **Round trip.** Export, import into an empty store, export again: the two files are identical apart from the header. The store's insert sets `updated_at` on a memory it marks superseded; if that breaks the comparison, say exactly which field differs and why, and record it. Do not weaken the comparison any further.
6. **The functions** (B-79). Expose these, with the argument order you prefer and no daemon type:
   - `share(store, scanner, project, repo_root, &ShareParams) -> Result<ShareReply>`
   - `sync(store, chunker, chunk_params, project, repo_root, &SyncParams) -> Result<SyncReply>`
   - `migrate(store, chunker, scanner, chunk_params, &MigrateParams, cwd_project) -> Result<ImportReport>`
   - `export(store, &ExportParams) -> Result<ExportReport>`
   - `import(store, chunker, scanner, chunk_params, &ImportParams) -> Result<ImportReport>`
   - Every error is an `sm_core::error` code with a message and a next action. The functions are synchronous and hold no process-global state.

## Acceptance tests and other tests

Use `SimpleChunker`, a temporary store, and temporary git repositories driven by the git command line. Give every test git process an isolated configuration (`GIT_CONFIG_GLOBAL` pointing at an empty file, `GIT_CONFIG_NOSYSTEM=1`, and an author name and email on each commit) so the user's global settings, such as commit signing, cannot change a result. Use the real `RegexSecretScanner` from `sm-capture` wherever a scanner is needed.

- **AT-8**, with both fixtures: every record is stored and the report matches the row count (`read` 10 and 6). Check the ids (kept UUIDs, B-12 for `mem-0001` …), the timestamps unchanged to the microsecond, the hashes (record 5's, and record 4's recomputed after redaction with the version 1 value in `imported`), the namespace rule (record 2 adds no tag), record 3 in the default project, record 4's key and secret gone from the content and from keyword search, record 6's Markdown unchanged. Keyword search finds a migrated memory while every chunk is still pending. Then embed every pending chunk with `FakeEmbedder` through `pending_chunks` and `set_embeddings`, as the daemon's queue will, and check that every memory has embedded chunks and nothing is left pending. A second run inserts nothing and counts every record in `skipped_existing`. A run stopped after its first batch resumes.
- **B-35 and B-79:** no project for a record and none to fall back on gives `project_unresolved` with the store unchanged; two projects with one name give `invalid_input` with the store unchanged; a `host/path` value creates a `git:` project with that remote, any other value a `name:` project.
- **AT-9** (`share` side): a memory holding fake credentials from `redaction_cases.json` (stored directly, past `remember`'s redaction) is written redacted with the kinds listed; a memory with a credential in a tag or anchor is refused with `secret_detected` and no file is written.
- **The format:** render, parse and render again give the same bytes for every type and status, with and without each optional key, with a body that holds headings and a fenced code block, and with Windows line endings in the content. Each malformed case (an unknown key, a nested value, a multi-line value, `schema: 2`, a bad id, a bad tag) is refused with its line.
- **`share`:** the path and slug, the `.gitattributes` file, replacing an earlier file after a type change, refusing a path held by another id, refusing an already-shared memory, `not_git_repository`.
- **`sync`,** over a repository you commit to: a new file is added as shared, pending, and marked; an unchanged file is not read again (count the blobs read); a metadata change revises without new chunks; a text change brings new pending chunks; a deleted file retracts and a restored file reapplies; the author's local copy is adopted when the hashes match and reported when they differ; an id in two files, or in another project, is reported and not applied; a malformed file is reported and the rest applied; uncommitted edits are ignored; a repository with no commits syncs nothing; `dry_run` writes nothing; a `supersedes` target is inserted first and marked superseded. Then the full loop: `share` from one store, commit, `sync` into a second store, and the memory arrives with the same title, body, type, tags and anchors.
- **`export` and `import`:** the round trip; refusing an existing file; one project by name, `not_found` and two names; an unknown format and a newer version refused before writing; an interrupted import resumed; a link with a missing end reported; shared memories and supersessions kept.

Run the tests on Linux in Docker as well (the `rust:1.95-trixie` image has git); the `CREATE_NO_WINDOW` path is Windows only.
